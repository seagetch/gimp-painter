The original contract checker required every handle implementation column to be
TODO, and therefore rejected the newly verified JsonResourceRef and partial
ActionGroupRef routes. It now admits only those two exact reviewed registry rows,
with nineteen pinned receipt identities and their source-bound validators. All
88 remaining TODO rows, historical type coverage and76 C-entry contracts remain.
This does not turn route implementation into whole-feature or old-layout parity.

The exact committed5743843dde checkpoint plus the checker/test overlay passes
90-handle/76-entry validation and8 test groups. Negative subcases reject12 row
field edits,38 missing/tampered receipts,25 source mutations, unknown claims,
reviewed-claim rollback and incomplete TODO contracts. Child validation runs in
isolated Python so PYTHONOPTIMIZE cannot silently disable its assertions.

At capture, the live worktree already contains a subsequent unverified preset
GUI header extension. The checker correctly rejects that source drift; this
receipt is explicitly the committed checkpoint, not a current whole-worktree
PASS. Successor implementations must supply their own current proof and retain
immutable prior receipts; changing a hash without new verification is not enough.
