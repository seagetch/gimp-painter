# Color Exchange old INT8 writer/type oracle

This is a **source-derived minimal writer experiment on GLib2.84.4**, not a genuine old GIMP execution/capture. It extracts verbatim bodies from `afa43fae3e920210146abed514f136fd49f671b5`: old INT8/INT32/ImageID/DrawableID GType registration, filter-value emitter, big-endian integer writer and NUL-string framing. Only return types/static scope are reattached. Successful bounded byte I/O is supplied by a FILE host; unused kinds are disabled, float fails if reached, and debug prints are suppressed. The exact original scalar/context GTypes are instantiated. An earlier successful adapter-kind stage is retained separately; final evidence removes those kind adapters.

The original `GimpInt8` derives from `G_TYPE_UINT`. Its writer branch nevertheless calls `g_value_get_int`, a signed getter. On the installed checked GLib host, **every call emits a critical and returns zero**. The isolated host counts only that exact expected critical and keeps it nonfatal; this does not alter application logging or excuse unrelated diagnostics. Each of256 cases supplies nine channel values `(case +29*channel) mod256`, so every channel sees every byte. All2304 supplied values are independently read back using the proper unsigned getter before serialization. The resulting256 frames all contain zero INT8 payloads, with2304 expected criticals per normal and ASan/UBSan run. LSan is disabled.

A separate Python big-endian serializer checks every byte: exact17-byte NUL-terminated `plug-in-exchange` name preceded by four length bytes; run-mode INT32 frame12; omitted ImageID8; omitted DrawableID8; nine INT8 frames9each; END8, total **138 bytes**. The run mode remains the signed bit pattern -123. Mutating the literal writer to the unsigned getter or the old INT8 parent type is rejected by the unchanged oracle.

This demonstrates the mismatch's behavior on the tested GLib build, **not a universal claim about every historical GLib build** (for example, library check configuration may differ). It does not identify what a user originally selected from a zero byte. A future decoder must restore only the bytes actually present in the capsule, retain the original capsule unchanged, and never infer lost nonzero parameters. Nonzero synthetic payload tests may verify byte-preserving admission, but must not be described as values emitted by this tested original writer. Malformed/unknown data must remain opaque. No production decoder, native Save/Open, parameter UI, or original16.022 completion is included here.
