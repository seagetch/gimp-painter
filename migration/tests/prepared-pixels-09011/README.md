# Prepare-only native pixel payload

Prerequisite **09.011/native-pixel-preparation**. New internal `prepare_pixels()` prepares independent exact-native-format rollback pixels without stealing the native snapshot, changing painted pixels, opening an Undo group, clearing redo, publishing history, or thawing previews. Null means a clean/clipped-empty operation; invalid, expanded, stale or failed preparation throws. The caller must hold its lifecycle transition guard.

`PreparedPixels` owns temporary transaction leases on native core, drawable, image, current buffer and original baseline. **Never store the complete PreparedPixels in image history:** its strong image lease would form a cycle. A combined Undo must retain the returned pixel buffer and item itself, copy the rectangle/start coordinates, and release the temporary preparation object after publication/cleanup. Accessors are borrowed while this object lives.

`matches()` detects native transaction/baseline identity, target buffer/format, original bounds, actual buffer extents, start coordinates and dirty bounds changing before publication. It is not synchronization against arbitrary external writes. Geometry expansion is explicitly rejected; the full paired caller must retain its existing rollback path or implement a complete resize/layer-mask payload, not silently commit a partial one.

Fifteen real native tests include24 precision/model/alpha cases; exact baseline bytes; unchanged painted bytes, native rollback snapshot and existing redo identity; clean and injected buffer allocation failure; stale geometry/coordinates/dirty bounds; replaced buffers; detach; actual same-pointer GEGL extent mutation; lifetime after caller destruction; and allocation-time reentry rejection. The application configuration explicitly enables oncanvas UI. Tests are model-only, not rendered-UI proof. Xvfb is authenticated1080×1920. Six selected production/test units are instrumented by ASan/UBSan (not dependencies, whole application, vptr or leak detection).

Three compiled mutations copy painted instead of original pixels, skip the final reentry check, or steal the native baseline. All fail meaningful native assertions; restored runs pass. C++14/noRTTI first/double-inclusion probe validates the new header boundary.

This implements preparation only. The original paired pixel/evaluator/resource Undo task remains open: a single combined Undo entry, explicit publication outcome (including observer-expired successful history), allocation-free historical state exchange and native finish(FALSE) cleanup are separate integration work.
