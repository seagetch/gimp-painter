# Typed native stroke Undo entry

Bounded prerequisite **09.011/native-stroke-undo** restores the original `gimp_mypaint_core_undo_get_type` source name as a native `GimpDrawableUndo` subclass. This is not the old direct `GimpUndo` layout or raw `Stroke*` ABI. The construct-only `stroke` property is a distinct native GObject type whose BindingStore owns a typed `shared_ptr<StrokeState>`. No raw C++ payload is stored in a GObject field.

The factory returns an owned, fully initialized, unpublished entry. It acquires endpoint leases through stack weak witnesses before callback-capable refs/allocations, rejects detached/replaced endpoints, mismatched formats, nonzero buffer origin and overflowing bounds, and rechecks after construction. It deliberately does not ask whether an active controller is ready to Undo: entries are constructed while a stroke is ending.

Native pop preflight acquires a dedicated state lease before history moves. Ordinary BindingStore close cannot revoke this lease. Native parent payload freeing is deferred through dirty/clean callbacks, class pop, update callbacks and final planner notifications. Finish clears its lease before callbacks, releases the state once, then completes any pending parent free. Unpublished disposal also releases native item/buffer references exactly once.

`StrokeState::apply` must install immutable historical state without exceptions, allocations or callbacks. It runs immediately before the native parent pixel swap, so update observers see coherent pixels and historical state. Dirty/clean observers before class pop see the old pair. Native pixel-copy allocation retains the existing fatal/no-return-error behavior; this proof does not claim recoverable whole-process OOM atomicity.

Sixteen actual native cases cover three Undo/Redo cycles despite transient state, active rejection without stack movement, coherent update observers and rejected nested Undo/Redo, free/dispose before and during pixel pop, unpublished lifetime, the typed property, expired-owner no-op, invalid construction, preparation-time disposal, recursive finish, duplicate guard acquisition, and constructor toggle detachment. State implementations in this bounded fixture are controlled test doubles; real Engine/Resource/controller pairing is a separate prerequisite and the original whole paired-Undo task remains open.

Tests explicitly enable oncanvas UI and run authenticated Xvfb at 1080×1920. These are model/lifecycle tests, not visible-UI screenshots. Nine selected native/BindingStore/test units use ASan/UBSan with production no-RTTI ABI (vptr and leak detection excluded); dependencies and the whole application are not instrumented. Four compiled mutants move state after pixels, free native fields too early, omit state restoration, or omit payload notification batching. Restored tests pass. C11 and C++14 first/double-header inclusion probes validate the new boundary.

## GEGL callback atomicity correction

The initial thirteen-case checkpoint passed drawable update observers but did not establish the complete callback contract. A new actual payload-buffer observer using the required `gegl_buffer_signal_connect` exposed historical-state=1/live-pixel=2 during the native live→payload copy; exact causal red source and result are archived. A preliminary plain `g_signal_connect` probe missed payload emissions because GEGL explicitly requires its specialized connection API; that failed setup is retained privately, not counted as evidence of absence.

The correction balances documented `gegl_buffer_freeze_changed`/`thaw_changed` via RAII on the retained **payload only**. The live buffer remains unblocked so GEGL graph invalidation precedes native drawable update. On a257×193 multi-tile image, every live changed callback checks every target pixel, and each drawable update observer queries the actual projection and checks all pixels. Both payload/live changed callbacks observe coherent state, reject nested history, and may free/dispose the native entry without releasing its state guard early. A nested external payload freeze across Undo and Redo receives no premature callback and exactly one accumulated region notification on its final thaw. Aliased/shared-storage payloads are rejected rather than suppressing live graph notifications. Ordinary Undo classes are unchanged.

The native helper captured by final tests is exact committed publication-outcome checkpoint2981a1bf28. The later, independently owned Filter-derived-cache refusal changes that one file in main; dependency-checkpoints.json binds its tested predecessor, without claiming the untested successor. All other non-held current inputs remain exact. Ordinary prepared18 and pop-guard11 regressions pass on this same captured native helper.
