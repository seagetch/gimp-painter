# Color Exchange typed raw raster and ROI transport

This checkpoint adds an actual RGBA8 raw raster kernel and typed `FilterColorExchangeOptions`/original-layout overloads to the existing sole point-shadow transport. Existing operation enum values and legacy overloads are unchanged. The private callback template reuses zero-fill, CropRaster, bounded writes, progress, cancellation and vector publication rather than creating another backend. Native FilterLayer/PDB admission is NOT implemented by this checkpoint.

The original exchange loop allocates `drawable->width * bpp` and indexes `x * bpp` as signed int. Unlike older iterator/ValueInvert routes, it does not multiply crop width×height. New preflight therefore retains the old RGB3 versus RGBA4 row domain while separately checking promoted RGBA8 transport in64-bit. Existing point routes retain their INT32 crop-area guard. Fake rasters prove Exchange admits46341² and original maximum row widths without allocation/I/O when already cancelled; original overflowing row widths are rejected before I/O. These tests do not claim successful enormous file allocation or processing.

Normal and selected five-translation-unit ASan/UBSan (C++14/no-RTTI, vptr/LSan excluded) pass90 options/layout/ROI scenes through vector, aliased vector and real temporary-file raster transport; exact full/partial/outside ROI and copied alpha/source bytes;130 raw/shadow read/write/final-flush cancellation and storage-error ordinals preserving completed vector publication; mutable caller options changed at first read or zero-write without affecting the captured operation. First/double header inclusion and all four previous enum values are checked. Three actual production mutants are rejected: applying the unrelated area limit, retaining raw mutable options, retaining shadow mutable options.

All existing point-shadow tests run unchanged afterward, including RedEye117,440,512 raw comparisons/60 ROI scenes, MaxRGB and ValueInvert exhaustive cases and retained original PDB point fixtures, existing signed-area rejection, cancellation, spill, progress and aliases. Current Edge code is linked as an unused dependency but no Edge operation or old Edge/string runtime is invoked. Initial missing pkg-config environment and preceding narrower receipts remain preserved separately.

Original RGB callers must promote alpha255 and pass their true source layout; invalid layouts are rejected. Gray/indexed/high precision admission, nine-byte parameter validation/binding, native selection/component/alpha-lock merge, owner-generation/lifetime checks, actual Filter UI and XCF roundtrip remain the subsequent native route task. In particular no partial private shadow is publishable after cancellation/failure and no_merge must retain original pixels.
