# Pinned applied-zoom source oracle

Revision `afa43fae3e920210146abed514f136fd49f671b5`. This is **source-only arithmetic**, not execution of the old application, an old GTK event loop, or old device runtime. Twenty-five extracted function bodies are byte-identical to the pinned source and separately hashed/ranged in `zoom-source-manifest.json`. Existing rotation fixtures and their manifest are untouched.

Include `zoom-oracle.inc` from C after ordinary GLib/Cairo prerequisites. Public state `LegacyAppliedZoom` supplies viewport/image sizes, old **double** offsets, old scale_x/y, zoom factor/minimum/maximum, image/monitor resolution, dot-for-dot, rotation and mirror. Invoke `legacy_applied_zoom_apply(&state, requested_factor, focus, pointer_input)`. Focus constants are `LEGACY_AZ_POINTER`, `LEGACY_AZ_IMAGE_CENTER`, `LEGACY_AZ_BEST_GUESS`, `LEGACY_AZ_RETAIN_CENTERING`. Explicit pointer input carries current coordinates, event origin (none/canvas/window/menu), and optional queued point. Queue consumption is reported; an equal-factor no-op does not consume it.

The boundary adapter supplies image metadata and controlled GTK event/pointer access. The queue uses actual GLib push/pop/slice operations. Zoom model `zoom`, `zoom_step`, `get_factor`, `set_property` and shell `scale_changed` are unchanged old functions. Only GObject property/notification transport is substituted: value is a real GValue, the unchanged old setter applies custom bounds and its changed-value notification invokes the unchanged old scale-changed function. UI repaint, title/ruler updates, pause/resume and zoom-revert-history side effects are no-ops. Resize-window-on-zoom is fixed false: this oracle does not model GTK window resizing. One call at a time is required by the controlled pointer context.

Important old behavior retained:
- Focus consults queued/current pointer and current-event origin, independently of the radial drag's passed coordinates.
- Full inverse applies old centered rotation/mirror before adding double offsets and dividing each anisotropic axis scale.
- Target offsets are assigned to `gint` using the **requested** scale; only subsequently does the zoom model clamp the actual factor to global `[1/256,256]` and configured bounds. Pre-clamping the request would change old applied origins.
- Draw scaled dimensions truncate floating products. Scroll clamp instead uses old `SCALEX/Y` with `RINT(x)=floor(x+0.5)` (pinned `libgimpmath/gimpmath.h` lines67–76), then integer overpan bounds with `OVERPAN_FACTOR=0.5`. For odd viewport sizes, half-pixel limits truncate again; e.g8192−151/2 becomes integer8116, not8117.
- Starts-fit and retained-centering decisions use the unchanged old helpers. Centering uses integer division and integer target offsets. Rotation does not silently substitute current rotated-bounding-box geometry.

`state.trace` is diagnostic, not an alternative result oracle: requested/applied factors, focus/image-center, pre-clamp integer target, starts-fit/center flags and actual post-clamp positions are exposed. To obtain focus diagnostics the wrapper replays the unchanged focus getter against explicit input, then restores the optional queue point before the normative unchanged scale call. Actual clamp positions are recorded at the existing scrollbar-update no-op boundary, after old clamp execution. No extracted body is edited for tracing.

Seven assertion groups include independent hand-computed pointer/queue/menu, anisotropic, rotation/mirror, min/max/custom-clamp and starts-fit results, plus7680 controlled1080×1920 geometry combinations. These portrait dimensions are numeric oracle inputs, **not Xvfb/UI screenshots**. Focused ASan/UBSan/float-cast-overflow instruments this standalone extraction and adapter only; GLib/GObject/Cairo remain uninstrumented and LSan is off. Four private-copy old-source mutations must be rejected. The first hand-written clamp expectation used8117 instead of integer8116 and the first grid cardinality expected15360 instead of7680; both arithmetic expectation errors were corrected before verified results, with no extracted-body change.

Reproduce with `zoom-extract.py`, `zoom-build-adapter.py`, `zoom-run-checks.py`, then `zoom-verify.py`, using the pinned dependency pkg-config environment. The apply boundary assumes valid finite old state and conversion-safe requested geometry; it does not define old undefined/out-of-range integer-conversion behavior. Native/current application comparison and rendered UI evidence belong to the consuming navigation test, not this standalone source oracle.
