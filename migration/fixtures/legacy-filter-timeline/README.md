# Original FilterLayer execution timeline (02.013)

This is source-instrumented execution of pinned original afa43fae3e920210146abed514f136fd49f671b5, not a port simulation. A separately copied configured build uses the pre-existing original installed plug-ins. No install command or prefix write was performed. Before/after SHA-256 records verify only installed bin/gimp-2.8 remained byte-identical; they do not seal the entire prefix, edge executable or shared libraries historically. runtime-byte-inventory.json hashes the current edge executable and loader-resolved dependencies after capture, with an explicit executor timestamp; it is not a retroactive before/after seal or historical process-map inventory. Maintained source, shared ledger and security settings were not changed, and binary interposition was not used. Measurements are single-process host monotonic microseconds, not wall-clock times or a performance promise.

## Measured scope

Six fresh GUI-initialized original core-app executions on authenticated loopback Xvfb, repeated with fresh profiles: one asynchronous plug-in-edge layer; insertion of a second lower edge layer while the upper runs; cancellation immediately after launch; cancellation after a progress-value observation; removal while running; synchronous built-in brightness/contrast. Source data are fixture-authored 256x256 solid-color layers. A subsequent source edit measures legitimate requeue, except in detached/built-in cases. Each observation window is 1500ms. The harness drives lazy projection tiles through normal pickable reads and iterates the real main context. It does not call completion manually or force scheduler state.

Core IDs and addresses identify layers within a process. `ordinal` is an observer's per-layer run-attempt counter, NOT an original generation token; the original has no generation ID or stale-generation guard. `run-return-running` precedes asynchronous completion and establishes nonblocking return for this procedure. `progress-end-callback` is the host's progress-end callback, NOT a worker OS-process exit timestamp or proof of success. `shadow-merge-enter` may occur even on an invalid invocation; only `shadow-merge-applied` records return from the actual apply-region call. `drawable-update-signal` and propagation boundaries show synchronous notification nesting, not an atomic modern staged-cache commit. `composite-cache` marks original cached-layer compositing. No worker-thread/process timestamp is fabricated.

## Observations and limits

Normal edge executes, applies pixels, ends, propagates, and returns to pending=0; a later source edit produces another run. The stack scene records original repeated stop requests, lower-layer completion, and upper-layer requeue. Immediate cancellation is too early to guarantee a connected plug-in progress cancellation handler, and the plug-in can finish normally afterward. Headless exploratory captures are separate: original progress-cmds.c skips progress init/update when no_interface is true, so they cannot establish the GUI cancellation path. The GUI late-cancel scene receives progress, issues cancellation, then receives end without any shadow-merge-applied for ordinal 1; a subsequent source edit completes ordinal 2. The original progress cancellation handler closes the plug-in with kill_it=TRUE. The capture does not measure OS termination directly. End callback alone is not successful completion. Detached original layers can receive end and propagation callbacks while attached=0; this fixture retains the object and is not a use-after-free test. The detached plug-in can fail on invalid drawable attachment. Built-in brightness applies synchronously yet has no measured end callback, leaving pending=1 and active=1 at the end of the bounded observation. This is not corrected here.

The original mutates drawable tiles in place, including source-cache copies before execution and shadow merge before callback. It does not implement the port's staged generation semantics. `new_runner` requeue is instrumented but not asserted as observed; its mere presence is not coverage. Stack-unblocked requeue is observed. The source already declares `cancel()` returning bool without a return; this experiment does not repair it.

Only the timeline row's bounded measurement scope is proposed for acceptance. No universal cancellation guarantee, full responsiveness benchmark, user-driven GUI interaction, native port parity, reader/XCF compatibility, pixel fidelity across versions, or complete scheduler acceptance is claimed. Existing pagecurl registration and shutdown Script-Fu diagnostics are retained in logs. Earlier exploratory captures (no lazy-tile validation, intermediate observer versions, and unavailable UNIX display) remain in the isolated workspace. The headless logs are delivered separately as diagnostic evidence, not interchangeable GUI execution evidence.
